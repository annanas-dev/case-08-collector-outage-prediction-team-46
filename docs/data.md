## Схемы

### Журнал событий (`ext-journal-YYYY.csv`, `журнал_событий_пример.csv`)

| Колонка | Тип | Пример | Примечание |
|---|---|---|---|
| `ид_события` | int64 | 4224123461 | **не уникален**, см. ниже |
| `ид_канала_данных` | int | 196736 | FK → справочник каналов |
| `дата` | date | 2026-01-01 | |
| `время` | time | 00:00:00 | московское время |
| `тревожное` | bool | `f` / `t` | в примере журнала `false` / `true` |
| `значение_датчика` | str | `0.01`, `28`, `Норма` | число (измерение) или текст состояния |

### Справочник каналов

`ид_канала_данных`, `тип_инж_системы`, `тип_датчика`, `тег_инженерной_системы`, `название_датчика`, `ид_объект` (FK → справочник объектов).

Типы по подсистемам:

| `тип_инж_системы` | `тип_датчика` |
|---|---|
| Газовая охрана | Газовый датчик |
| Температурная подсистема | Датчик температуры |
| Пожарная охрана | Тепловой датчик, Датчик дыма, Ручной извещатель, Состояние УИР-Р |
| Охранная подсистема | КД АВ, КД Дверь, КД Люк, Датчик движения, Стекло, 9-секционный люк |
| Диспетчерский контроль | Состояние насоса, Состояние вентилятора, Состояние фазы, Состояние охраны, Датчик затопления, Переключатель |
| Диагностическая подсистема | ИБП |

`тег_инженерной_системы` (например `15-11.1.131.2.`) уникален у каждого канала. Организаторы разрешили его удалить.

`название_датчика` у большинства каналов содержит пикет: `ГАЗ Д26 ПК746`, `Темп. ВШ ПК88,5`, иногда в нижнем регистре (`пк212`). Это единственная доступная «локация», координат нет.

### Справочник объектов

`ид_объект`, `иерархия_уровень`, `родитель`, `вид_объекта`, `диспетчерское_название_объекта`.

- уровень 1: 1 объект `district` («Район по эксплуатации», 5773); его родитель 3831 в справочнике отсутствует;
- уровень 2: 16 объектов `controlHouse`;
- уровень 3: 78 объектов `controlHouse` / `guardObject`.

Каналы привязаны только к объектам уровня 3.

### Справочник состояний

`тип_датчика`, `ид_набор_состояний`, `название_состояния`, `тревожное`. 10 типов, 33 тревожных состояния из 62.

Тип датчика в этом справочнике не совпадает с типами из справочника каналов (например, «Затоплен» указан у датчика движения, а в журнале приходит от насоса). Тип канала брать из справочника каналов.

## Технические особенности формата

Только то, что нужно учесть в коде. Как это обнаружено и проверено – в ноутбуке `notebooks/01_preprocessing`.

1. `ид_события` не уникален: у измерений и у состояний свои последовательности ID. Ключ записи – (`ид_события`, `класс_записи`). Дедупликация только по полной строке, порядок событий канала – по `дата_время`.
2. В файлах есть полные дубли строк и строка заголовка посередине файла (2025) – удалять.
3. Флаг `тревожное` записан как `t`/`f` или `true`/`false`. Приводить к bool, не пересчитывать по тексту состояния.
4. `значение_датчика` хранит число (измерение), текст состояния или дату (`01.01.1970 03:00:00` у «Состояние охраны» – нулевой timestamp, то есть пропуск).
5. В журнале есть каналы, которых нет в справочнике каналов. При join их не отбрасывать (`left`).
6. Время в журнале московское. Spark пишет timestamp в Parquet как UTC-момент: `spark.read.parquet` и `toPandas()` в сессии `annanas.spark.get_spark` отдают московское время, а `pd.read_parquet`/pyarrow – наивный UTC (на 3 ч раньше). Из pandas читать только через `annanas.aggregates.read_vitrine`.

Пишет `notebooks/04_features` (построение, проверки и отбор признаков – там).

`datasets/processed/features/object_day_states.parquet` – смены состояний каналов справочника (Spark):

Сутки с маской (включая «плановые работы АКМ») не входят в историю признаков: события этих суток выброшены, в долях они выпадают и из числителя, и из знаменателя. Признак `дней_после_ппр` – сутки с конца последнего окна ППР АКМ объекта (`maintenance/ppr_windows.parquet`), закончившегося до `D`, не больше 365; у объектов без газовых каналов – NaN:

| Столбцы | Тип | Что это |
|---|---|---|
| `ид_объект`, `день` | int64, date | ключ; `день` – момент прогноза 00:00 (date, как в `target.parquet`) |
| `цель_<класс>` (8 столбцов) | int8 | цели, как в `target.parquet` (включая `цель_неисправность_охраны`) |
| `маска`, `выборка`, `период_смву`, `эпоха_флага` | string | как в `target.parquet`; строки с маской не для обучения и оценки |
| признаки | float32 | отобранные признаки; признак суток `D` вычислен только по данным до `D 00:00`; список, смысл и окно – в каталоге |
| `базовый_прогноз_<цель>` (7 столбцов) | float32 | частотный прогноз: доля суток с целью на объекте за 30 суток до `D` (`features.window_shares`: знаменатель – сутки окна без маски, тихие сутки подключенного объекта – нули; без таких суток – средняя доля на обучении); цели `отказ, пожар, подтопление, любой_инцидент, газ, потеря_связи, неисправность_охраны` |

С ними и справочником каналов `build_all(cut(S, D), grid, ctx)` дает для суток `D` те же признаки, что в `features.parquet`.

`datasets/processed/features_catalog.parquet` – все построенные признаки, по строке на признак:

| Столбец | Что это |

| `подъем_отказ`, `подъем_пожар`, `подъем_подтопление`, `подъем_любой_инцидент` | одиночный PR-AUC признака / доля положительных, обучение без масок |

| `psi_валидация`, `psi_эпоха`, `psi_после_смву` | PSI обучение → валидация; до → после смены разметки флага (валидация + тест); обучение после перехода СМВУ → валидация |

| `факт_<цель>` | int8 | метка цели |
| `выборка` | string | `валидация` / `тест` |

## Чего нет относительно ТЗ

Нет журнала ОДС (подтвержденные инциденты, решения диспетчера, ложные срабатывания), заявок и плановых работ, паспортных данных оборудования, координат, метеоданных.
